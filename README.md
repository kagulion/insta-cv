# ProstoCV

Веб-редактор резюме, который работает прямо в браузере. Экран разделён пополам: слева форма, справа лист A4, и он меняется сразу, как только вы что-то вводите. Регистрация и сервер не нужны: всё, что вы ввели, хранится в браузере и никуда не отправляется. Готовое резюме можно распечатать или сохранить в PDF.

![Редактор ProstoCV: форма слева, лист A4 справа](preview.png)

## Как пользоваться

1. Заполните поля слева. Обязательны имя, должность, «О себе» и хотя бы один контакт, остальные секции по желанию. Пустая секция в резюме не попадает.
2. Справа виден лист A4 ровно таким, каким он выйдет на бумаге. Пунктир показывает, где примерно пройдут разрывы страниц.
3. Нажмите «Печать / PDF» (или Ctrl+P) и выберите принтер или «Сохранить как PDF». Если что-то не заполнено, редактор предупредит и подсветит поля.

На телефоне вместо двух колонок вкладки «Редактор» и «Превью».

### Где хранятся данные

Только в этом браузере (localStorage), сохранение автоматическое. Ссылки на резюме нет и не будет. Поэтому:

- **«Экспорт»** скачивает резюме JSON-файлом. Это резервная копия и способ перенести резюме на другой компьютер или в другой браузер.
- **«Импорт»** загружает такой файл обратно.
- **«Демо»** открывает пример, **«Очистить»** начинает с пустого листа. Оба спрашивают подтверждение.

В приватном режиме браузер может запрещать сохранение. Тогда под кнопками появится предупреждение: сделайте экспорт перед уходом.

## Резюме с помощью ИИ-агента

Агент задаёт вопросы о вашей карьере, вы кликаете по вариантам или отвечаете коротко. По ответам он собирает файл `resume.json`: структурирует текст и подбирает формулировки, понятные рекрутёрам и ATS, но ничего не выдумывает.

1. Склонируйте репозиторий и установите зависимости (нужен [Node.js](https://nodejs.org) 22.12 или новее):

   ```bash
   corepack enable
   pnpm install
   ```

2. Откройте папку проекта в ИИ-агенте (Claude Code, Codex, Cursor, Copilot, Gemini CLI и других) и напишите: «составь моё резюме». В Claude Code можно вызвать `/build-cv`.
3. Отвечайте на вопросы. Цифры и достижения агент будет спрашивать у вас.
4. Агент проверит файл командой `pnpm check-resume`. Откройте редактор, нажмите «Импорт» и выберите `resume.json`.

Как это устроено: агенты читают `AGENTS.md`, откуда попадают на [инструкцию](.claude/skills/build-cv/SKILL.md). Файл `resume.json` в `.gitignore`: в нём личные данные.

## Разработка

Нужны Node.js 22.12 или новее и pnpm 11 (`corepack enable` подтянет его сам).

```bash
pnpm install
pnpm dev
```

Откройте http://127.0.0.1:5173.

| Команда                    | Что делает                                        |
| -------------------------- | ------------------------------------------------- |
| `pnpm dev`                 | Dev-сервер с горячей перезагрузкой                |
| `pnpm build`               | Сборка в `dist`                                   |
| `pnpm preview`             | Просмотр собранной версии                         |
| `pnpm test`                | Тесты (Vitest)                                    |
| `pnpm check`               | Проверка типов                                    |
| `pnpm lint`, `pnpm format` | ESLint и Prettier                                 |
| `pnpm check-resume [файл]` | Проверка файла резюме, по умолчанию `resume.json` |

### Технологии

Vite и TypeScript, интерфейс на Preact с `@preact/signals`, данные проверяет zod, стили на Tailwind CSS со шрифтом Geist, иконки из Lucide и Font Awesome Brands. Качество кода: ESLint, Prettier, Vitest.

### Как устроено

| Папка         | Что внутри                                                                  |
| ------------- | --------------------------------------------------------------------------- |
| `src/config`  | Схема резюме на zod, нормализация контактов, тексты интерфейса по умолчанию |
| `src/state`   | Черновик в signals, автосохранение, формат файла и миграции                 |
| `src/editor`  | Форма: секции, поля, редактор списков, ошибки, печать                       |
| `src/preview` | Вёрстка резюме и лист A4 в iframe                                           |
| `src/data`    | Демо-резюме                                                                 |
| `src/styles`  | `theme.css` общие токены, `app.css` редактор, `resume.css` лист резюме      |

Главные решения:

- **Две проверки одной схемой.** Строгая (`validateConfig`) даёт ошибки под полями. Мягкая (`previewConfig`) всегда отдаёт данные для превью: пустые обязательные поля допустимы, неверные значения (почта, ссылки) отбрасываются, остальное резюме продолжает рисоваться.
- **Превью в iframe.** У листа свои стили, своя ширина 210 мм для брейкпоинтов и своя печать: кнопка печатает только iframe. Вариант Tailwind `print:` внутри листа срабатывает всегда, поэтому экран совпадает с бумагой.
- **Формат файла с версией.** Экспорт и localStorage используют один конверт `{ app, version, cv }`. Если меняется форма данных, поднимите `DRAFT_VERSION` в `src/state/envelope.ts` и добавьте миграцию в `src/state/migrations.ts`: старые файлы и сохранения догонят новую схему.
- **Секции-списки описаны данными** в `src/editor/specs.ts`, их рисует один `ListEditor`. Новое поле секции добавляется в схему, в описание формы и в компонент секции в `src/preview/sections`.
- **Иконки брендов:** в сборку попадает только список из `src/config/brand-list.ts`, а не весь набор Font Awesome. Новый бренд добавляется туда.

## Публикация

Workflow `.github/workflows/deploy.yml` при пуше в `main` проверяет проект (линт, формат, типы, тесты), собирает его и выкладывает на GitHub Pages. Один раз включите в настройках репозитория Pages → Source → GitHub Actions. Сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

Пути в сборке относительные, поэтому папку `dist` можно выложить на любой статический хостинг, в корень домена или в подпапку.
